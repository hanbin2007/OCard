评审编制：Rust 与前端各开两路**独立**评审并行跑 —— Opus 与 gpt-5.6-sol(`max`)。
四份报告交叉比对后收敛。两边独立指到同一处的，一律按较高的那个严重度处理。

## 一、这次评审真正值钱的地方

不是"多找了几条"，而是**三条靠读代码想不出来、只能靠实测发现**的问题：

### 1. 审计日志是「可格式化」的第四条呈现路径

后端 `commands/tasks.rs` 专门把 `sourceFolders` 写进了 `COPY_COMPLETED` 载荷，
注释写着「审计必须记下这次的范围」。前端 `lib/audit.ts` 的 `KNOWN_FIELDS`
白名单里没有它，`auditDetails` 取满 4 项就 return，**永远走不到"露出生键值"
那条兜底**。于是：

```
部分拷贝 {…, sourceFolders:["DCIM/100MSDCF","PRIVATE/M4ROOT/CLIP"]}
   界面这一行 =「拷卡完成」+ 容量 39.1 GB          ← tone: ok（绿）
整卷      {…, sourceFolders:[]}
   界面这一行 =「拷卡完成」+ 容量 39.1 GB          ← 逐字相同
```

屏内提示会被「拷下一张卡」覆盖、toast 会消失、铃铛会被确认清掉 ——
**审计日志是事后判断「这张卡能不能格式化」的唯一权威记录**。前三处修得
再对，也拦不住第二天回来核对的人看到一条绿色的「拷卡完成」。

### 2. E2E 新增的浮层不变式抓不到它自己宣称的病灶

用真实 CSS + 该用例逐字复刻的合成 DOM 在 headless Chrome 里实测：

| 场景 | 结果 |
|---|---|
| 只删 `.overlay` 的 `grid-template-rows`（它宣称要抓的那件事） | **全绿** ★ |
| 删 `grid-template-rows` + 删 `.drawer/.dialog` 的 `overflow-y`（提交前的真实状态） | 红 ✓ |

同一提交里加的 `.drawer{overflow-y:auto}` 把症状盖住了 —— 它守住的只是
「两个修复同时被撤销」。原用例注释里那句「这里钉的是样式层的定律」
**名不副实**。

### 3. 契约测试的默认方向是「不认识就放行」

`overflow.test.ts` 三类逃逸、`sticky.test.ts` 四类逃逸。最要命的一条：
`sticky.test.ts` 遇到**任何首字符不是 `.` 的选择器**（后代选择器、`#root …`、
`div.x`、`[data-x] .y`）就整条跳过 —— 这不是白名单收窄，是解析器直接失明；
而自检只要求「至少扫到 4 条」，现有 5 条稳稳撑住，**退化根本察觉不到**。

同类的还有：`minmax(0, 1rf)`（单位打错）、`minmax(0, var(--nope))`（变量不存在）
浏览器整条丢弃、100% 复现原病灶，契约却判绿。

**结论写成规矩**：静态契约的默认方向必须是 **fail-closed** —— 不认识的写法
一律判红。

## 三、我做的两个裁决

### 裁决一：点开头的条目，从「一律跳过」改成明确列举的系统项白名单

原行为：`name.starts_with('.')` 一律 `continue`。配合「整卷 100% 完成 →
本卡可格式化」，卡上合法的 `.clip.mov`、被误设隐藏属性的素材从未进入计划，
任务却报 100%。

**改。** 这是备份工具，**漏拷却报成功**是最不能接受的失败形态；可见告警
只能缓解，不能替代拷对。只排除明确列举的系统项（`.Trashes`/`.fseventsd`/
`.Spotlight-V100`/`.DS_Store`/`._*`/`System Volume Information` 等），
每一条都要注释写明它是什么、为什么排除，**不许用「以点开头」这种形状判据兜底**。

### 裁决二：`plan_digest` 纳入 mtime

原摘要只覆盖 `(source_rel, target_rel, size)`。**同大小、内容被替换**
恰恰是它漏掉的那一类，而这在换卡场景里完全可能发生。

**加。** 令牌的全部意义是「你批准的就是将要执行的」。代价是误报风险，
所以要求错误信息必须能区分三种原因（文件集变了 / 只有 mtime 变了 /
卷身份变了）—— **说错原因比不说更糟**，会把人引向错误的排查方向。

### 一处我接受了实施方的反对意见

我要求在 `copy.rs:844` 也套用统一名字键。实施方拒绝并给了理由：
NFC 键进了规划器与全计划预检之后，「两个计划项落到同一物理文件」已经在
预检 fail-closed；而在那里加「实名与请求名不符即失败」的闸，会把
**FAT 把文件名大小写改掉之后的正常续传**判成失败 —— 制造新的假失败。
理由成立，采纳。统一键补在了 `notice_target_name_clashes` 这一处真正做
名字比较的地方。

## 三·补 · 裁决一带出来的连锁，以及它顺手挖出的旧洞

把「点开头一律跳过」改成白名单，逼出了三处**本来就存在、方向相反**的问题：

1. **群晖 `@eaDir` 不以点开头**，旧判据一路放行 ——
   `@eaDir/SYNOPHOTO_FILM_*.mp4`（群晖给视频自动生成的低码率预览）
   会被当成源素材去转码，`@eaDir` 本身会被当成一个相机夹递归进去，
   缩略图还给分类计数灌水。
2. **`.ocardpart` 也不以点开头**，所以旧判据从来没挡住过它 ——
   它今天已经能被 `packaging` 打进交付包，而那是断连时按设计留下的
   **半截文件**。交付一个截断的文件比漏掉它更坏。
3. `curated_flow_hints` 用 `rsplit_once('.')` 切主名，放行点开头的名字之后
   `.alpha` 与 `.beta` 的主名双双塌成空串、被判成同一件 ——
   会提示用户删掉一份毫不相干、还没修完的原稿。

所以六处口径最终**全部统一**（零例外），名单新增 `SYSTEM_ITEM_SUFFIXES` 一类。

**变异验证抓到的唯一一处假绿**也在这里：把六处判据改回旧写法之后，
分类计数那条测试**没有变红** —— 漏数 2 个点开头素材、多数 2 个不以点开头的
垃圾，总数正好抵消。改成 3 个点开头素材让两种错误无法相消后才变红。
两种错误互相抵消导致的假绿，是这一类「计数型断言」的通病。

## 四、明确记入债务、本轮不动

codex 报了 9 条 P0，其中 5 条**不是本次改动引入的**，改动面大且牵涉其它流程，
混进这一轮会把本来能验收的东西一起拖住。逐条核对过确实都在 `04da593` 之前：

- `fsx.rs:37` —— no-replace 在不支持的文件系统上回退成可覆盖的 `rename`
- `.ocardpart` 按文件名猜所有权并直接删除
- 复制期间源文件稳定性未校验（缺复制前后 `fstat` 比对）
- `manifest.rs:170` —— 固定 tmp 名 + 跟随链接 + 并发无 lease
- `tasks.rs` resume 的「返回成功但没有 worker」竞态

其余：

- `--border`（普通分割线）浅色 1.31:1 / 深色 1.20:1，`.input`/`.select` 的
  静息边框用的就是它，按 WCAG 1.4.11 同样是失败项。改它波及全 App 每一条
  分割线，单独排一轮。
- 浅色三档文字被压扁：`--text-tertiary #646464` 与 `--text-secondary #5d5d5d`
  只差 7 阶。要同时满足 AA 和三档层级，得整体重排文字灰阶。
- 画廊胶片条已窗口化，但主网格 `VirtualGrid.tsx` 视口高度为 0 时静默回退成
  渲染 6 行的老问题仍在（本次未触碰）。

## 五、留给实机验收的

以下都只在单测 / 静态核算 / headless Chrome 里验过，**没有在打包好的
Tauri 应用里目视确认**：

1. 连拍组全屏层的滚动与 `overscroll-behavior`、确认框抬层。
2. 对比度修复后边框整体变重的观感（`--border-strong` 从 `#cdcfd1` 收到
   `#7b7e82`，最差组合 3.15:1，基本是刚好过线的最浅值，但比以前硬）。
3. 抽屉滚动修复（Chrome 量通只是必要条件；上一轮的教训是浏览器与
   WKWebView 可能分支不同）。
4. `nfc_nfd_on_real_fs_lands_one_target_per_source_entry` 在 macOS 上是
   **弱测试** —— APFS 归一不敏感，两个名字在创建时就被合并成一个源文件，
   断言退化为恒真。真正的判别力在 Linux CI 腿上与两条纯函数变异测试。
